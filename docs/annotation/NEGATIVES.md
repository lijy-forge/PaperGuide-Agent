# 负样本怎么标

先说清楚一件事：**现有的检索用例不需要负样本**。召回率只问"该找到的找到了几篇",
没找到的是什么无关紧要。

负样本是为**决策评测**准备的——量的不是"检索得好不好",而是"判断得对不对"。这两件
事会独立失败：一个系统可能检索能力很强但判断很差（什么都纳入),反过来也成立。

## 两个决策点

### 决策 A：这篇论文该不该选入核心文献

`MetadataRelevanceGate` 先按元数据初筛,`EvidenceAwareFinalRelevanceService` 再按
证据复核。**过度纳入**就是把不相关的论文写进综述——和"过度检索"是同一类错误。

- **正样本**：该被选入。已有 46 条（就是三个用例的 `ground_truth`）
- **负样本**：**检索会返回,但不该被选入**

负样本的关键在后半句。随便找篇无关论文没有意义——系统本来就不会检到它。有价值
的负样本是**主题相邻的近似样本**：同一领域、关键词重叠,但不回答这个问题。

好消息是这批样本已经存在了：**`docs/annotation/REVIEW.md` 里我判定为「不该纳入」
的那些**,正是从同一次检索里出来、主题相邻但被排除的论文。MEC 20 篇、SLAM 35 篇。

### 决策 B：证据够不够写完整综述

`EvidenceSufficiencyAssessment` 决定出完整综述还是降级为证据有限综述。**该降级不
降级**,就是拿不足的证据写出看起来很完整的报告——对"证据驱动"这个定位是致命的。

这个的负样本不是论文,是**证据状态**：只有 2 篇核心论文、或者验证通过的证据只有 3
条,这种情况该降级。标注对象是场景不是文献,需要单独构造。

## 步骤（决策 A）

**第一步：确认负样本清单**

用 `REVIEW.md` 走一遍复核（见 `PROMPT.md`)。复核完成后：

- 确认「该纳入」的 → 正样本
- 确认「不该纳入」的 → **负样本**

一次复核同时产出两类标注,不用标两遍。

**第二步：补充被漏掉的负样本**

复核清单只覆盖了 bib 里有的论文。真实检索会返回更多东西,其中一部分是更难判断的
近似样本。等 API 限流恢复后：

```bash
python -m evals.paperguide.annotate pool "你的问题" --limit 30
```

从返回结果里挑出**不在正样本里、但看起来很像**的,那些是最有价值的负样本——它们
才是系统真正容易判错的。

**第三步：多少条够用**

正负各 15–20 条就能算出有意义的一致率。不必凑到 90 条。样本量决定的是置信区间,
而这里要看的是"优化前后有没有显著变化",不是精确估计。

## 我能做什么、不能做什么

**能做**：从 bib 和检索结果里筛出候选、按主题相邻度排序、生成待判定清单、
把判定结果写进用例文件、实现评测逻辑。

**不能做**：替你下判断。我只能读标题,判断"这篇是否回答这个问题"需要读过论文。
我在 `REVIEW.md` 里已经给出了初判,但那是**待复核的建议,不是标注**。

我按标题判错的概率不低——之前从 PDF 提取标题时,20 篇里就有 5 篇提错了。
